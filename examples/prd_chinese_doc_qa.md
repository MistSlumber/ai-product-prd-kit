# 一页 PRD 实例：中文文档问答（RAG 基线版）

## 1. 目标用户与真实任务

用户手上有一批会更新的中文资料，需要「对着资料问一句，拿到带出处的准确回答」。当前靠全文搜索逐份翻文档，同义提问搜不到，直接问通用模型又会编造不存在的条款，错误引用有实际代价。

## 2. 需求四道门

| 门 | 答案 | 证据 |
| --- | --- | --- |
| ① 代价 | 通过 | 查证耗时，错引条款有返工成本 |
| ② 必要性 | 部分通过 | 关键词搜索能解决精确匹配，同义改写与拒答做不好 |
| ③ 可行性 | 通过 | 自有 Markdown 语料 + 20 条带标注评测集 |
| ④ 可验收 | 通过 | Recall@3、MRR、带引用正确率、P95 延迟均有基线 |

**四道门全过，进入 POC。**

## 3. 能力边界与兜底

- 只依据检索到的片段作答；资料里没有的明确回答「资料未提供」，不靠常识补全；
- 每条结论附 `[Q编号]` 引用，可回溯；
- 零命中或低置信时转人工，不生成看似合理的补全；
- 离线模式不调用外部服务，便于审计与复现；
- 明确不做：微调、多租户、全量语料入上下文、收录非自有版权资料。

## 4. 指标与上线门槛

| 层级 | 指标 | 当前基线 | 上线门槛 |
| --- | --- | --- | --- |
| 检索质量 | Recall@3 | 0.8500（BM25，20 题） | ≥ 0.95 |
| 检索排序 | MRR | 0.7917 | ≥ 0.90 |
| 结果质量 | 带引用答案正确率 | 待测 | 人工抽检通过率 > 85% |
| 结果质量 | 拒答型误答率 | 待测 | < 5% |
| 任务效率 | P95 延迟 | 待测 | < 4.2s |
| 成本 | 单个成功任务成本 | 待测 | 记录并设上限 |

三条已知未命中案例（同义鸿沟）公开记录在配套仓库 README，不作为演示掩饰项。

## 5. 成本测算

见 `ai-product-prd-kit` 的 `scripts/cost_report.py` 三方案对照。示例参数下人工兜底占总成本 94%+，因此降本优先级是「减少转人工 → 缩短人工时长 → 模型分层与缓存」，而不是先砍模型单价。

## 6. 灰度与监控

先离线跑评测集，达标后再接生成；上线记录检索片段、提示词版本、模型、token、延迟与答案；坏例回流进评测集形成回归闭环；严重错误率超阈值即回滚到「只出检索片段、不生成答案」模式。

## 7. 明确不做

不做多租户、不做模型微调、不做全量语料入上下文、不收录任何非自有版权资料。
