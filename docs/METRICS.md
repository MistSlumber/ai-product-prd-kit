# 四层指标与上线门槛

| 层级 | 指标示例 | 怎么验收 | 常见错误 |
| --- | --- | --- | --- |
| 结果质量 | 带引用答案正确率、faithfulness、拒答型误答率 | 人工抽检固定评测集 | 只看几个漂亮样例 |
| 任务效率 | 平均节省时间、P95 延迟、单次成功耗时 | 埋点统计 | 只报平均值，长尾超时被掩盖 |
| 业务结果 | 一次解决率、转人工率、投诉率、复用率 | 业务系统对照 | 用模型指标冒充业务指标 |
| 风险边界 | 严重错误率、越权调用次数、无依据结论占比 | 规则 + 抽检 | 没有「严重」的定义 |

## 上线门槛写法

门槛必须是**数值 + 验收方式 + 负责人**，例如：

- 人工抽检通过率 > 85%（固定 50 条评测集，每周一次）
- P95 延迟 < 4.2s（生产埋点，连续 7 天）
- 严重错误率 < 0.5%（定义：给出无来源且会造成实际损失的结论）
- 拒答型问题误答率 < 5%（评测集中「资料里没有答案」的 10 条）

## 检索与生成分开看

- 检索阶段：`Recall@k`（有没有捞到）、`MRR` / `NDCG`（排得对不对）。召回阶段漏掉的片段，生成再强也补不回来。
- 生成阶段：答案正确性、faithfulness、引用完整率。
- 上线后：转人工率、单个成功任务成本。

**不要把不同阶段的指标混成一句「准确率 90%」。**

## 评测集要求

固定、进版本管理、覆盖事实型 / 跨片段推理型 / 拒答型三类；只增不改历史样例。线上坏例回流后追加，任何策略改动都在同一批问题上回归。参考 `rag-strategy-benchmark` 的做法。
