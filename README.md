# ai-product-prd-kit

AI 产品落地的一页 PRD 模板、指标口径与**单个成功任务成本**测算工具。面向「要不要立项、怎样算做好、方案哪个更省」这三个产品决策，不谈模型结构。

## 快速开始

```bash
python scripts/cost_report.py
python -m unittest discover -s tests -v
```

零第三方依赖。第一句命令输出三种方案的成本对照表并写入 `results/cost_report.json`。

## 核心口径：算的是「单个成功任务」，不是「单次调用」

| 变量 | 含义 |
| --- | --- |
| `price_per_call` | 一次模型调用单价 |
| `calls_per_attempt` | 一次尝试内的调用次数（Agent 多步会 >1） |
| `success_rate` | 一次尝试的成功率 → 期望尝试次数 = 1 / 成功率 |
| `cache_hit_rate` | 命中缓存的比例，命中则不调模型 |
| `tool_cost_per_attempt` | 检索 / 工具固定开销 |
| `human_fallback_rate` / `human_minutes` / `human_hourly_cost` | 转人工的比例、耗时与人力成本 |

```
单次尝试成本 = 调用次数 × (1 - 缓存命中率) × 调用单价 + 工具开销
自动部分成本 = 单次尝试成本 ÷ 成功率
人工成本     = 转人工率 × (人工分钟 ÷ 60) × 小时成本
单个成功任务成本 = 自动部分成本 + 人工成本
```

**为什么不用单价**：便宜模型若成功率低、需要多次重试并转人工，单个成功任务可能比一次答对的贵模型更贵。`tests/test_cost_model.py` 里有专门的单调性测试锁住这个口径。

## 实测对照（示例参数，可复现）

| 方案 | 单个成功任务成本 | 期望尝试次数 | 模型成本 | 工具成本 | 人工成本 |
| --- | --- | --- | --- | --- | --- |
| 分层 + 缓存 + 工具兜底 | **0.3128** | 1.14 | 0.0105 | 0.0023 | 0.3000 |
| 模型分层 + 缓存 | 0.7649 | 1.25 | 0.0137 | 0.0013 | 0.7500 |
| 全用强模型 | 1.4333 | 1.39 | 0.0833 | 0.0000 | 1.3500 |

### 这张表最该看的一列

**人工成本占了总成本的 94%–96%，三项模型成本加起来不到 7%。** 也就是说，在这些参数下，把模型单价再砍一半，单个成功任务成本几乎不动；真正决定成本的是**转人工率和每次人工处理时长**。降本优先级应当是：① 减少转人工（提高自动一次解决率、加确定性兜底）→ ② 缩短人工处理时长（把检索结果和依据提前备好）→ ③ 才是模型分层与缓存。

> 参数是示例假设，用于演示口径与敏感性，不代表任何真实业务成本。换成你的实际数据只需改 `scripts/cost_report.py` 里的 `SCENARIOS`。

## 仓库里有什么

| 文件 | 用途 |
| --- | --- |
| `docs/REQUIREMENT_GATES.md` | 立项四道门：有人付出代价吗 / 不用 AI 能否解决 / 数据与上下文齐备吗 / 知道怎样算做好吗 |
| `docs/PRD_TEMPLATE.md` | 一页 PRD 骨架，含能力边界、兜底、灰度与「明确不做」 |
| `docs/METRICS.md` | 四层指标表与上线门槛写法，区分模型指标与业务指标 |
| `examples/prd_chinese_doc_qa.md` | 填好的实例：中文文档问答 |
| `src/cost_model.py` | 成本模型与参数校验 |
| `scripts/cost_report.py` | 方案对比与 JSON 输出 |
| `tests/` | 8 项测试：单调性、边界校验、成本拆解求和、排序 |

## 常见反模式

为 AI 而 AI；没有评测集就上线；只盯模型指标不看业务；上下文无限增长导致成本失控；提示词没有版本管理；**用单次调用单价汇报降本成果**。
